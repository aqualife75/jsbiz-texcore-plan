# 증거 이미지·도식 구조화 규칙 — 심사위원이 그림만 보고 기술성·사업성을 판단하게 (tp-writer 계획 · tp-designer 실행)

> 원칙: **글은 그림을 설명하고, 그림은 주장을 증명한다.** 10쪽 신청서에서 그림 1장은 문장 10줄보다 싸고 빠르다(충북대 파트 II). 장식 이미지는 0장. 모든 그림은 "무엇을 증명하는가"가 캡션 아래 한 줄로 붙는다.

## 1. 그림의 자격 — 넣기 전에 세 가지를 답한다
1. **어느 심사위원 질문에 답하는가?** (form_map의 속마음 질문) → `proves`에 쓴다.
2. **숫자·비교·실물 중 무엇을 보여주는가?** 셋 중 하나도 없으면 넣지 않는다.
3. **출처가 있는가?** 팀 자료(Tier A)·인용 캡처(Tier B)·웹 이미지(Tier C, `needs_human_review`)·생성 도식(generated, 입력 숫자의 출처를 캡션에).

## 3. 배치 규칙
- 그림은 **소제목 바로 아래, 글보다 먼저**. 소제목 → 그림 → 글(3~4문장) 순.
- 폭: 단독 150mm(본문 폭), 2장 나란히 각 74mm, 3장 격자(`evidence_board`)는 150mm 1장으로 생성해 넣는다.
- 높이: 1장이 본문 1/3쪽(약 80mm)을 넘지 않게. 넘으면 `width_mm`를 줄이거나 2장을 나란히.
- 섹션당 최대 3개(limits). 그림이 많으면 표로 바꾼다(표는 그림으로 세지 않는다).
- 팀 이미지(사진·화면·그래프)는 **원본 그대로**(가공·보정 금지). 흐리거나 작은 이미지(`quality: low`)는 쓰지 않고 `[이미지 확보 필요]`로 `to_secure`에.

## 4. 캡션 형식(세 줄, hwp_fill이 그림 아래에 넣는다)
```
[그림 2] 3차 시제품 필드테스트 결과 — 20명 × 경사 8°, 전복 0건          ← caption (70자 이내, 무엇이 보이는가 + 핵심 숫자)
→ 증명: 핵심 기능(4방향 무게중심 제어)이 실제 사용자 환경에서 작동함          ← proves (70자 이내, 어느 질문의 답인지)
출처: 팀 자체 시험 기록(2025.11) / 사진: 팀 제공                              ← source (90자 이내)
```
- 생성 도식의 출처는 입력 숫자의 출처를 쓴다("출처: 팀 사실 팩·KOSIS 2024, 도식은 작성자 재구성").
- 가상·설명용 수치는 캡션에 "(설명용 예시)"를 반드시 붙인다. 실제 제출본에는 설명용 예시가 남으면 안 된다.

## 5. 표 규칙
- 표 캡션 "[표 n] …" 위에, 출처줄 아래에. 헤더행 굵게. 7열·12행 이내, 셀 90자 이내(넘치면 두 표로).
- 비교표의 열 순서: 비교 기준(심사위원 질문) → 대체재 A → 대체재 B → **우리** → 우리에게 의미. 우리 열에 X 1개 이상(약점 공개가 나머지를 믿게 한다).
- 비용표: 항목·수량·단가·금액·산출 근거. 합계 = 지원 예산 + 자부담.
- 일정표: 월 열 12개, 행은 제품·고객·인증·자금 4줄, 활동 막대 말고 **◆(숫자로 끝나는 결과)**.

## 6. 도식 데이터 작성(tp-designer가 `figures[].data`에 채움) — 숫자 출처 의무
- 모든 숫자는 사실 팩·증거 원장에 있는 값만(`harness trace`가 figures.data도 검사). 없으면 그 칸을 "[확보 필요]"로 두고 to_secure.
- 라벨은 20자 이내, 한 칸에 한 사실. 그림 안 글자는 본문보다 적어야 한다(그림이 또 하나의 문단이 되면 실패).
- 색은 생성기 기본(네이비·슬레이트·◆ 빨강)을 바꾸지 않는다. 신청서 전체에서 같은 색이 같은 의미(빨강 = 우리/마일스톤)여야 한다.
